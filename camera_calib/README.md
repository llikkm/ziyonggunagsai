# 单目相机标定 + 平面尺寸测量（OpenCV 实操包）

> 项目总览、模块地图、当前状态与全套测试：见 [PROJECT_README.md](PROJECT_README.md)。本文件只讲相机标定/平面尺寸测量这一段。

一个可以直接在 Windows + 已装 OpenCV 的电脑上跑通的最小工程，对应三步实验：
**识别棋盘格角点 → 标定内参和畸变 → 用标定结果测量板上实际尺寸并与尺子对比**。

```text
camera_calib/
├─ make_board.py           生成可精确打印的标定板 PDF（矢量，20mm 格）
├─ capture_images.py       摄像头实时采集：检测到合格姿态才存盘
├─ calibrate.py            标定：角点 → 亚像素 → calibrateCamera → 质量报告
├─ measure.py              board=留出集一致性验证，object=卡尺独立尺度验证
├─ diagnose.py             查"为什么这张图检不出棋盘格"，逐张给结论
├─ calib_lib.py            共用：检测/标定/单应/去畸变
├─ selftest_synthetic.py   没相机时用合成真值验证整条链路是否可信
├─ board/                  生成的标定板
├─ data/calib, data/val    拍的照片（calib=参与标定，val=没参与，用于验证）
└─ out/                    calib.json、报告、检测缩略图、去畸变对比、测量 CSV
```

## 0. 准备（约 15 分钟）

**打印标定板**

```powershell
python make_board.py
# board/chessboard_9x6_20mm.pdf
```

打印时**必须**选「实际大小 / 100%」，关掉「适合页面」「缩放以适合」，纸张 A4。
打完用游标卡尺量 PDF 上那条标称 **180 mm** 的横线（越长相对误差越小），记下实测值 `D`：

```
实际格边长 = 20.00 × D / 180.00
```

例如量到 179.3 mm → 格边长 19.92 mm。后面所有命令都用这个值传 `--square 19.92`。
这一步不要省：普通打印机缩放误差 0.3%~1% 很常见，**它会被原样带进所有测距结果**。

**贴板**

- 贴在平整硬板上（亚克力、铝板、厚卡纸+双面胶都行），四周留 ≥1 格白边。
- 板子翘曲是 RMS 变差的第一大原因，贴之前用直尺比一下。
- 打印面避免反光：哑光纸更好；实在反光就把相机曝光调低或换个角度。

**环境**

```powershell
pip install opencv-python numpy        # matplotlib 只用于生成预览图，可选
python -c "import cv2; print(cv2.__version__)"
```

`findChessboardCornersSB` 需要 OpenCV ≥ 4.6（`opencv-python` 4.6+ 自带，不需要 contrib）。
版本低也没关系，脚本会自动退回 `findChessboardCorners + cornerSubPix`。

## 1. 步骤一：让 OpenCV 识别棋盘格

两种方式，推荐用采集脚本（它同时解决"拍 20 张不同姿态"这件事）：

```powershell
python capture_images.py --camera 0 --cols 9 --rows 6 --target 20
```

窗口里会实时画出检测到的角点（彩色连线，顺序为逐行从左到右）并提示：

| 提示 | 含义 | 怎么做 |
| --- | --- | --- |
| `searching for board...` | 没检出 | 让整块板进画面，别只拍一角 |
| `blurry` | 清晰度不够 | 停住别动，等自动对焦；光线不足就补光 |
| `pose too similar` | 和已有图姿态太像 | 换距离/换倾角/换位置 |
| `ok - auto saving` | 合格 | 停 0.5 秒自动存盘 |

画面被分成 3×3 网格并显示每格的样本数，**每格至少 2 张**再退出，这样标定参数在整幅画面上才可靠。

不想用摄像头，也可以直接拍好照片丢进 `data/calib/`（PNG/JPG 都行，按文件名顺序读取）。

**拍摄要点**

- 15~25 张，覆盖：正对、左右倾斜、上下倾斜、远近、绕光轴旋转四个角度。
- 板子要**整块**在画面内（含白边），不要贴边裁掉。
- 固定在三角架上，标定过程中**不要动相机**，也不要去调焦距/分辨率。
- 画面亮度稳定、别过曝（黑白格都还能看出边缘就算正常）。
- 存 PNG：JPG 在黑白边缘会有振铃，直接吃掉亚像素精度。

**亚像素定位**

`calibrate.py` 里做的是：SB 检测器自带亚像素；退回经典路径时用
`cv2.cornerSubPix`（11×11 窗口，100 次迭代或 1e-6 px 收敛）把角点压到亚像素。
可以单独看效果：

```powershell
python calibrate.py --dir data/calib --show     # 逐张弹窗
```

## 2. 步骤二：内参标定

```powershell
python calibrate.py --dir data/calib --square 19.92
```

输出 `out/calib_report.txt`，形如：

```
内参矩阵 K (像素):
  [    979.394   0         641.159 ]
  [ 0          973.541   356.847 ]
畸变系数: k1=-0.276185, k2=+0.062437, p1=+0.000717, p2=-0.000439, k3=+0.176979
垂直/水平视场角: 66.32° x 40.59°  (由 fx,fy 反推)
重投影 RMS 误差: 0.1278 px
```

**怎么读**

| 指标 | 合格 | 说明 |
| --- | --- | --- |
| RMS 重投影误差 | < 0.5 px 好，< 1 px 可用 | 每张图的平均误差，脚本会列出每张图、>1px 标红 |
| fx 与 fy 差 | < 1% | 差太多说明板不平或姿态单调 |
| 主点 cx | 接近 w/2（±5%） | 偏离大说明角点分布偏一侧 |
| 每张图 rms | 彼此接近 | 某张明显偏高 → 用 `--exclude 文件名` 剔掉重标 |

把可疑图剔掉再跑一次，对比 RMS 是否下降：

```powershell
python calibrate.py --dir data/calib --square 19.92 --exclude calib_07.png calib_13.png
```

**必须做的目视检查**

- `out/detections.png`：每张缩略图上角点应稳稳落在黑白格交点上，没有整体偏移、没有跳格。
- `out/undistort_*.png`：左边原图、右边去畸变图。原来向外弯的直线应该变直。

`out/calib.json` 就是后面测量要用的内参，别删。

> `calibrateCamera` 的映射关系：`objpoints`（板上 3D 坐标，mm）、`imgpoints`（像素坐标）、
> `mtx`（=K）、`dist`（k1,k2,p1,p2,k3）、`rvecs/tvecs`（每张图的外参）。
> 官方教程：<https://docs.opencv.org/4.x/dc/dbb/tutorial_py_calibration.html>

## 3. 步骤三：测量实际尺寸

### 3.0 验证集照片的要求（比标定图更严一点）

`data/val/` 里的图不参与标定，所以要单独拍。硬性要求：

| 项目 | 要求 | 不满足会怎样 |
| --- | --- | --- |
| 相机状态 | 同一台相机、同一分辨率、标定后**没动过**焦距/分辨率/数字变焦 | 内参失效，图能检出但测出来偏几个百分点（最隐蔽） |
| 板子完整性 | 整块在画面内，四边留 ≥ 1 格（20 mm）白边 | 角点检不全 → 直接报"未检出" |
| 板子像素尺寸 | 板宽 ≥ 画面宽度 1/3；单格 ≥ 25 px，最好 ≥ 40 px | 1200 万像素裁到很小时，SB 检测器失效 |
| 清晰度 | 静止拍摄；板区域的 Laplacian 方差 > 40 | 模糊 → 角点漂移，RMS 变大 |
| 曝光 | 白格不糊成纯白、黑格不糊成灰；避免直射反光 | 边缘被冲掉，角点定位不准甚至检不出 |
| 姿态 | 倾角 15°~45°，别超过 50° | 太斜时格子被压成细条，检不出/精度差 |
| 覆盖 | 至少 3~5 张，位置、距离、倾角各不相同；其中 1 张让板子靠近画面边缘但完整（检验畸变） | 只测到一个位置 → 验证不出畸变是否修好 |
| 文件 | 原图 PNG，不裁剪、不缩放、不旋转、别用微信/QQ 转发 | 压缩和缩放会改分辨率、丢细节 |

`--cols/--rows` 一律填**方格数**（9×6 格就填 9 和 6）。填成角点数（8 和 5）会变成 7×4 的模板，直接检不出；
填反（6 和 9）反而不报错，只是把板坐标系转了 90°，测距结果仍然对——所以别拿"能跑通"当参数正确的证据。

### 3.1 留出集一致性验证（board）

另外拍 5 张**没有参与标定**的图，放到 `data/val/`：

```powershell
python measure.py board --dir data/val --calib out/calib.json --square 19.92
```

每张图会给出板中心到相机距离、板面倾角，以及三条已知距离的实测值：

```
横向上边缘 8 格   标称 140.00 mm | 平均误差 -0.026 mm (-0.018%) | 最大 0.067 mm
纵向左边缘 6 格   标称  80.00 mm | 平均误差 -0.014 mm (-0.018%) | 最大 0.066 mm
对角线            标称 161.25 mm | 平均误差 -0.030 mm (-0.019%) | 最大 0.058 mm
```

注意这三条距离**仍然是由格边长推出来的**，只能证明"检测+畸变+单应"这条链路是自洽的，
发现不了"格边长本身印错了"。真正的尺度验证要用下面的方法。

### 3.2 独立尺度验证（object，推荐）

找一个用游标卡尺量过的薄物体（硬币直径、M3 螺丝长度、小零件两孔间距），
**平放在标定板上**（和板面共面），拍一张，然后：

```powershell
python measure.py object --image data/val/obj01.png --calib out/calib.json --known-mm 24.85
```

在弹出窗口里点物体的两个端点，立刻显示视觉测量值，并按 `q` 结束：

```
[1] 24.930 mm  卡尺 24.85  误差 +0.080 mm
本次共 1 次测量：24.93 mm
相对卡尺 24.85 mm：平均误差 +0.080 mm (+0.32%)，最大 0.080 mm
```

建议同一个物体测 5 次（换位置、换姿态），看**重复性**（标准差）和**准确度**（对卡尺的偏差）。
两者都有意义：重复性好但偏差大 → 多半是打印比例或格边长没量准；两者都差 → 检测/畸变有问题。

明细会写到 `out/measure_object.csv`，可以直接进实验记录。

**原理**（一句话）：标定板平面上的点与其像素满足单应 `[u,v,1] ~ H·[X,Y,1]`，
`H` 由该图检出的角点和已知板坐标算出，反变换就把像素点映回毫米。
所以要求：① 被测物与板共面；② 图像先做过去畸变；③ 板整块清楚可见。

### 3.3 检不出棋盘格怎么办

`measure.py` 只会说"未检出棋盘格，跳过"。想知道到底哪一条要求没满足，跑诊断：

```powershell
python diagnose.py --dir data/val --calib out/calib.json
```

它逐张给出：能不能读、分辨率是否和标定一致、原始图/去畸变后是否检出、清晰度、
灰阶跨度、板宽与最小格像素、倾角、到画面边的距离，最后一句人话结论：

```
文件                     分辨率  原始  去畸变  清晰度   灰阶   板宽px  最小格px   倾角°  边距px  结论
02_blur.png            1280x720     ✗       ✗       -      -        -         -       -       -  整幅都糊（最锐块清晰度 6）
                        → 对焦/抖动；手持 1/30 s 以下基本必糊
03_small.png           1280x720     ✓       ✓    9833    241       72        11      32     240  单格只有 11 px
                        → 拍近一点或提高分辨率（建议单格 ≥ 40 px）
04_cut.png             1280x720     ✗       ✗       -      -        -         -       -       -  黑白区域贴着画面边 —— 板子出画了
                        → 退一步或调整构图，四边至少留 1 格（20 mm）白边
05_rot90.png           720x1280     ✓       ✗    2028    242      389        45       -     161  分辨率 720x1280 与标定的 1280x720 不同
                        → 同一次实验别改分辨率/裁剪；否则内参不适用，需重标定
```

（上面是 `out/diagnosis_demo/` 里用合成图造的 8 种典型坏样本，可以拿来对照自己的照片。）

常见原因和对应处置：

| 结论 | 真实原因 | 处置 |
| --- | --- | --- |
| 整幅都糊 | 手抖、没合焦、1/30 s 以下曝光 | 三脚架 + 定时 2 s；先半按对焦 |
| 黑白区域贴着画面边 | 板子被裁掉一角 | 退一步；四边留 1 格 |
| 单格只有十几像素 | 拍太远 / 分辨率低 / 后期缩图 | 靠近拍或换高分辨率，单格 ≥ 40 px |
| 对比度偏低（灰阶跨度 < 90） | 欠曝、逆光、打印太浅 | 补光、换角度、重新打印（别用省墨模式） |
| 大面积过曝 | 灯/窗直射反光，白格打成纯白 | 关掉顶灯改用侧光；偏振片；降曝光 |
| 分辨率与标定不同 | 换了摄像头、改了分辨率、微信转过图 | 用原图重拍，或按新分辨率重标定 |
| 画面里找不到 8x5 角点 | 格数填错（填了 8/5 而不是 9/6）、换了另一块板、板太小 | 核对 `--cols/--rows` 与板上的方格数 |

## 4. 没有相机也能先验证代码：合成自检

```powershell
python selftest_synthetic.py
```

它用**已知的** fx=980、fy=974、cx=641.3 和 k1=-0.28… 渲染 20 张带畸变的棋盘格图，

| 项目 | 结果 |
| --- | --- |
| 内参恢复误差 | fx −0.063%，fy −0.047%，cx −0.14 px |

| 平面测距（去畸变） | 平均误差 0.048 mm（0.05%），最大 0.086 mm |

## 5. 精度预期与误差来源

用手机/笔记本摄像头、20 mm 格、距离 30~50 cm 的典型水平：

| 项目 | 量级 | 主要来源 |
| --- | --- | --- |
| 内参 fx/fy | 0.1%~0.5% | 图数、姿态覆盖、板平整度 |
| 平面测距（几十 mm） | 0.1%~0.5% | 打印比例、点击精度、去畸变残差 |
| 重复性（同一物体多次） | 0.05~0.2 mm | 角点噪声、光照 |

按影响从大到小排：

1. **打印比例没校准**（系统性，0.3%~1%）→ 卡尺量 180 mm 横线，改 `--square`。
2. **板不平**（系统性弯曲）→ 贴硬板、压平。
3. **没去畸变** → 用 `measure.py`，它自动去畸变（含裁边后的主点修正）。
4. **姿态太单一**（16 张全是一个角度）→ 采集脚本的 3×3 覆盖和姿态去重就是防这个。
5. **点击端点不准**（随机，±1 px ≈ 0.2 mm @ 30 cm）→ 放大画面、多点几次取平均。
6. **物体有厚度**（离板面 h mm，比例误差约 h/物距）→ 薄物体、或按 h/Z 修正。

## 6. 常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| `未检出角点` | 先跑 `python diagnose.py --dir data/val --calib out/calib.json`，它会指出具体是哪条不满足 |
| 同一目录有的图能检出、有的不能 | 多半是那几张糊了/出画/过曝，`diagnosis.png` 里能直接看出来 |
| 检测正常但测出来整体偏几个百分点 | 验证图分辨率或焦距与标定不一致（换了相机/改过分辨率/微信转过图） |
| 只检出部分角点 | 板子被裁掉一角，或强反光把某格吃掉了 |
| RMS 一直 > 1 px | 板不平 / 手抖模糊 / 分辨率太低 / 某几张姿态异常（看 detections.png） |
| `fx` 和 `fy` 差很多 | 姿态单调（只有平移没有倾斜），或标定板本身不共面 |
| 测出来整体偏大/偏小 1% | 打印缩放，用卡尺重定 `--square` |
| 测出来线性偏差随位置变大 | 畸变没去干净，检查 undistort 对比图 |
| 板子斜到 60° 时误差变大 | 平面外误差放大，尽量 < 45° |
| 打不开相机 | 关掉微信/腾讯会议/浏览器里占用摄像头的页面，换 `--camera 1` |

## 7. 这一步说明了什么、没说明什么

已经验证：图像质量可用、镜头畸变可建模、**尺度是自洽的**（板面内测距与卡尺一致）。

还没有验证：三维测量能力。现在所有测量都强制"被测点在标定板平面上"，
本质是单应变换，没有用到深度。要做三维，需要：
深度方向有约束（双目/结构光/ToF）、或已知物体几何模型做 PnP、或多视角三角化。
下一步如果做双目：用本工程分别标定左右相机内参，再做 `cv2.stereoCalibrate` 求基线，
那时测距才真正脱离"共面"假设。


## 附二：线激光三角测量（没有激光器时的仿真）

`laser_triangulation/` 用 NumPy 模拟相机、激光平面和 31 mm 台阶，验证“像素 + 相机内参 K + 激光平面 → 三维点 → 台阶高度”的核心数学，并给出像素噪声、焦距误差、平面标定误差的定量影响。它还会渲染带缺失/反光/亮度不均的合成激光图，走一遍和真实 webcam 相同的“提取 → 反算”链路。

先跑纯仿真（不需要相机和激光器）：

```powershell
cd laser_triangulation
python simulate_step.py
```
